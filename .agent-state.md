# Liferay Tunnel (lfr-tunnel) — Persistent Agent State

*This document maintains continuous state across AI coding sessions and provider transitions.*

## Active Development Status & Recent Completed Features
- **v1.44.24 (Released & Deployed)**:
  - **TUI Scrolling Requests Table (#1106 / PR #1113)**: Fixed `pkg/client/tui.go` request history rendering loop to display the 8 newest requests at the top, restoring real-time scrolling for captured HTTP traffic.
- **v1.44.23 (Released & Deployed)**:
  - **Automated Primary Region Failback (#1103 / PR #1111)**: Added `StartFailbackProber` background ticker in `pkg/client/interceptor.go` that periodically pings developer's primary regional edge node (`/api/healthz`). Re-registers on primary edge node, updates TUI headers, state files, and tunnels live without CLI restarts.
- **v1.44.22 (Released & Deployed)**:
  - **Same-User Lease Eviction & Primary Domain Assignment (PR #1109)**: Updated Central Gateway `CheckSubdomainForUser` and `Register` in `pkg/server/auth.go` to evict stale regional leases for the same user, ensuring primary `.se` domain is assigned to the new live tunnel connection during failover.
- **v1.44.21 (Released & Deployed)**:
  - **Multi-Part Chisel Remote Authorization Regex (PR #1107, #1108)**: Updated Gateway `allowedRemotes` regex in `pkg/server/auth.go` (`^R:.*:%d(:.*)?$`) to accept multi-part client remote strings (`R:127.0.0.1:49153:localhost:8080`).
- **Logged Issue #1112**:
  - `feat(edge): add state transition retry and debounce for edge node power actions` — Addresses EC2 400 `IncorrectInstanceState` when toggling edge node state transitions.
- **Logged Issue #1116**:
  - `TestResolveServerURL_OfflineRegionFallback depends on live production infrastructure` — `resolveServerURL` called `fetchRemoteRegions`, which overwrote the test's fixture with the live `/api/version` region map. Fixed by routing the network fetch and the `~/.lfr-tunnel` cache write through swappable seams (`fetchRemoteRegionsFn` / `saveRegionCacheFn`) and rebuilding the test on `httptest` edges.

## Active Operational & EDR Constraints
- **Local Test Execution (SentinelOne EDR)**:
  - MUST use `make test` ONLY (`LFT_TEST_DIR=/private/tmp/lfr-tunnel`).
  - FORBIDDEN from running bare `go test` or running `./bin/lfr-tunnel` directly (prevents EDR quarantines).
- **Binary Signing**:
  - Client binaries must be cross-compiled and signed via 1Password CLI (`op run -- ./bin/lfr-tunnel-ops sign`) before release/deployment.
- **Documentation Footers**:
  - Mandatory timestamp footers on all `.md` files: `*Last Updated: YYYY-MM-DD* | *Last Reviewed: YYYY-MM-DD*`.

## Current Focus (as of 2026-08-21)
Portal/server work is in good shape; attention has moved to the **client** side, in this order:
1. **Edge failover/failback correctness** — make region loss and primary recovery reliable, not just functional in the happy path.
2. **Client observability** — the interceptor currently keeps only a 100-entry in-memory ring of requests, lost on exit. Needs a persistent HTTP traffic log plus a separate error/diagnostic log so failover faults can be root-caused after the fact.
3. **TUI & Inspector TLC** — both have had far less attention than the portal.
