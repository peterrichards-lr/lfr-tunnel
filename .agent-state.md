## Unreleased on master (since v1.44.24)
Everything below is merged and awaiting the next tag.

- **Client failover/failback hardening (Epic #1119, PRs #1126 / #1127)** — five sub-issues:
  - **#1120** `performRegistrationHandshake` exited the process on *any* registration failure,
    and both recovery paths called it, so one transient 502 from a healthy replacement region
    killed the tunnel and dropped the lease. Split into `attemptRegistration` (classifies, never
    exits) plus a fatal wrapper used only for the initial startup registration. A 403 stays
    terminal. An HTML 502 from a proxy fails at the JSON decode step and matched none of the
    gateway-error patterns, so it previously reached `log.Fatalf`; now retryable.
  - **#1121** Failover could re-elect the region it had just left, and loop. The old code
    deleted the failed region from `cfg.Regions`, but `resolveServerURL` then called
    `fetchRemoteRegions`, which replaces that map wholesale and restored the entry. The
    exclusion only ever held when the failed edge was *also* unreachable over HTTP — which it
    is not in the lease-eviction path, where the edge is up and only the lease is gone. Replaced
    with a cooldown applied *after* the refresh, rediscovery from a host other than the failed
    one, and bounded retry across regions.
  - **#1122** Region/endpoint updates raced the TUI. Added `SetRegionEndpoint` /
    `RegionEndpoint` / `ConsumeFailback`. Added `TEST_BUILD_FLAGS` to the `test` target so
    `make test TEST_BUILD_FLAGS=-race` works while still building and running from
    `LFT_TEST_DIR`.
  - **#1123** One health-check goroutine per session instead of per mapped port. Previously each
    port ran its own ticker posting an identical status report to each endpoint (a portal plus
    three extensions produced eight POSTs every five seconds), each raced to trigger the same
    failover, and each overwrote the single `Status` field with its own port's result. Status is
    now aggregated and is `up` only when every mapped port is reachable.
  - **#1124** `pkg/client/interceptor.go` hardcoded `https://tunnel.lfr-demo.se` as the central
    control plane, so self-hosted deployments POSTed their session token, region and status to a
    third-party host every five seconds. Now taken from the gateway-advertised region list, with
    no hardcoded fallback, re-derived after failover, and compared on parsed host rather than
    substring. Same treatment for the server's `lfr-demo.se` reservation-promotion fallback.
- **Persistent client logs (#1128 / PR #1129)** — `~/.lfr-tunnel/logs/` now holds
  `traffic-<sub>.log` and `error-<sub>.log` as JSON Lines, written for foreground **and**
  background runs. Rotated (3 generations, 8 MiB) rather than truncated, and deliberately does
  not roll an empty file so start/stop cycles cannot flush real content through empty
  generations. `client-<sub>.log` moved alongside them; Inspector and GUI readers fall back to
  the legacy path. Bodies are off by default behind `-log-bodies`.
  - **Trap worth remembering:** the background console log handle must stay a real `*os.File`.
    `os/exec` passes an `*os.File` to the child as a file descriptor but wraps any other
    `io.Writer` in a pipe serviced by a goroutine in the parent — and a detached `-background`
    parent exits right after `Start()`, killing the child's stdout. Caught by the E2E UI suite.
- **#1125 (PR #1132)** — `Server.Start`/`Server.Stop` raced on `httpServer`/`redirectSrv`; now
  behind `httpServerMu`. Also fixed `handleEdgeControlWS` writing `auth_success` to the raw conn
  after publishing the `safeConn` into `s.edgeClients`, which let a concurrent broadcast
  interleave frames on one socket.
- **#1133 (PR #1134)** — admin alerts were silently disabled whenever
  `admin_notification_email` was unset, even with `owner.user_id` configured, because they are
  independent keys with no fallback and every send site returns early on empty. Magic links were
  unaffected (addressed to the user), which is why it presented as "some email works, some
  doesn't". Now defaults to `Owner.UserID` after the env overrides, and warns at startup when
  nobody is configured.
- **#1117 (PR #1118)** — removed LDM dev-box power tooling. Nothing here targets `aws-1`/`aws-2`
  and the E2E suites are pure Docker Compose, yet every PR was powering off a real LDM EC2
  instance while the hourly cron powered it back on. Belongs in `liferay-docker-manager`.
- **#1116 (PR #1115)** — made `TestResolveServerURL_OfflineRegionFallback` hermetic. It fetched
  the live production region list and elected regions by probing real edges, so it changed
  verdict with the edge power schedule.

## Open Issues
- **#1130** — TUI shows a hardcoded Inspector port (wrong whenever 4040 is taken or
  `-inspector-port` is used) and a hardcoded `127.0.0.1` target host, and truncates strings by
  bytes rather than runes, which can split the multi-byte characters the client's own log lines
  contain.
- **#1131** — remaining data races: `runEdgeControlChannel` shares a bare `*websocket.Conn`
  between its ping goroutine and read loop, and ~30 test assertions read `mockMailSender` fields
  without its lock. Pre-existing and unchanged in the deployed build.
- **#1135** — the two registration approval emails disagree on whether the admin notification
  preference applies. `handleVerifyEmail` always sends the approve link; `handleCompleteSetup`
  suppresses it when notifications are disabled, with a test asserting that. The owner's stated
  intent is that admins receive everything unless they opt out, *except* a set of emails that
  must be delivered regardless — but that policy was never expressed as a mechanism, so each of
  the six `NotificationPrefs == "disabled"` sites re-derives it. Slack (#909) may be intended to
  replace admin email entirely; decide that before building more here.
- **#1112** — edge node power action retry/debounce. Its premise needs re-checking: the EC2
  `IncorrectInstanceState` churn was most likely this repo's CI fighting the hourly cron, and
  that tooling was removed in #1117.

## Active Operational & EDR Constraints
- **Local Test Execution (SentinelOne EDR)**:
  - MUST use `make test` ONLY (`LFT_TEST_DIR=/private/tmp/lfr-tunnel`).
  - FORBIDDEN from running bare `go test` or running `./bin/lfr-tunnel` or `lfr-tunneld`
    directly (prevents EDR quarantines).
  - `make test TEST_BUILD_FLAGS=-race` is the EDR-safe way to run the race detector.
- **S1 also kills unrelated dev tooling.** A tool that suddenly looks broken or missing is often
  S1 collateral, not a missing install — seen on 2026-08-21 with colima (`lima not found`,
  later recovered) and Homebrew `node` (missing `libllhttp` despite `brew list` showing it).
  Work around it (`~/.nvm/versions/node/*/bin/node`) rather than reinstalling.
- **`golangci-lint` runs containerized only** —
  `docker run --rm -v "$(pwd)":/app -w /app golangci/golangci-lint:latest golangci-lint run`.
  It can OOM inside the colima VM while compiling the AWS SDK (`signal: killed` on
  `pkg/provisioner/aws.go`); that is a local resource limit, not a code defect. CI is
  authoritative.
- **Binary Signing**:
  - Client binaries must be cross-compiled and signed via 1Password CLI
    (`op run -- ./bin/lfr-tunnel-ops sign`) before release/deployment.
- **Documentation Footers**:
  - Mandatory timestamp footers on all `.md` files: `*Last Updated: YYYY-MM-DD* | *Last Reviewed: YYYY-MM-DD*`.
