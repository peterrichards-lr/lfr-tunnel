This Privacy Policy describes how this self-hosted Liferay Tunnel (lfr-tunneld) gateway processes your data. It is a summary of the project's full policy, which is linked at the bottom of this page; the section letters below are the same ones that policy uses.

1. Information We Collect & Process

A. Network & Tunnel Data

  • IP Addresses: The public IP address of the connecting client and of any visitor requesting a tunnel subdomain. Processed to route packets, enforce rate limiting and auto-ban protections, and log security events.
  • Bandwidth & Metrics: Bytes in and bytes out per active tunnel, for resource monitoring and usage analytics.
  • Tunnel Port Mappings: The local development ports you expose, used to multiplex connection handshakes.

B. User Authentication Data

  • Email Addresses: Processed for account verification, approval notifications, and passwordless magic link logins.
  • Profile Names: Optional first, last and preferred name, used to personalise the dashboard.
  • OIDC SSO Claims: If this gateway is configured for Single Sign-On, the standard profile claims your identity provider returns (email, given name, family name) are stored to provision your profile.

C. Administrative Audit Logs

  • Security Events: Registrations, login attempts, token creations and administrative status changes are recorded locally in the gateway database for auditing and security review.

D. Client Diagnostic Logs (Opt-In Only, Off by Default)

  • They stay on your machine by default: The lfr-tunnel client writes its own traffic, error and console logs to ~/.lfr-tunnel/logs on your computer. They are never uploaded unless you turn diagnostic log sharing on yourself, in Account Settings. It is off by default.
  • Withdrawal is immediate: Your setting is read when an administrator asks for logs, again before the request reaches your client, and once more when logs arrive — so turning it off applies at once, including to a client that is already running.
  • Request and response bodies are never uploaded, even if you run the client with -log-bodies. Personal access tokens, Authorization values and credentials in URLs or query strings are removed before upload.
  • Retention: Uploaded logs are kept in this gateway's database for at most 30 days. They are deleted immediately if you withdraw consent — the ones already collected are destroyed, not merely stopped — and immediately if your account is deleted. Routine backups taken before a deletion still contain the data until those backups age out.
  • Auditing: Every request, every refusal for lack of consent, every upload and every time an administrator opens a stored bundle is recorded in the administrative audit log.

E. Anonymous Geographic Distribution (Operator-Enabled, Off by Default)

  • Only if this operator enabled it: No geo-IP database ships with the gateway, so this is off unless the operator of this gateway deliberately obtained and deployed one. Off is the default.
  • A further use of the IP address in section A, not a new collection: When you register a tunnel, your public IP address is looked up in the operator's local database file and reduced to a two-letter ISO country code. No third-party service is contacted. Only the country field is read — never city, subdivision or coordinates.
  • The address is discarded: The lookup happens in memory and the address is dropped straight afterwards. Your address and your country are never written or logged together, and nothing can return the pair.
  • What is stored: One row per country per ISO week, holding a country code and a count. The table has no user column.
  • A minimum of 5 users per country: A country is recorded only once at least 5 distinct users have been seen there that week; below that it is folded into a single OTHER bucket, which is itself withheld until it too reaches 5. The threshold is applied before anything is written. Addresses that cannot be placed — private ranges, carrier-grade NAT, addresses absent from the database — are dropped rather than guessed.
  • Who can see it, and for how long: The resulting counts are visible only to gateway administrators. They contain no identifier of any kind, so they are kept as historical metrics rather than deleted on a schedule, and deleting your account neither removes nor needs to remove them.

2. Data Security & Storage

Personal Access Tokens (PATs) are stored on the server using secure SHA-256 cryptographic hashes. All data is stored in a local, private SQLite database and is never shared, sold, or transmitted to external servers.
